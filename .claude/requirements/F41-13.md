# F41-13 — `FormsPackageWorkspaceComponent` — the tabbed forms & package workspace

**Status:** PARTIAL
**Priority / Effort:** P1 / M
**Phase:** 1 (stage 1.5) — [Plan.md](../Plan.md) §5
**Source:** [`../input/pending/Section-4.1-Backlog.md`](../input/pending/) M5 T9
**Depends on:** `F41-03`…`F41-11` (all delivered)
**Blocks:** `DR-15`

## Requirement

A single tabbed workspace for the forms and package lifecycle of a case, reachable from case detail,
replacing the Milestone-2 mapping-review route as the entry point.

## Acceptance criteria

- [ ] `FormsPackageWorkspaceComponent` exists as the component loaded by the `forms-package` route
- [ ] Tabs cover the full lifecycle: **Mapping preview · Drafts · Readiness · Package & approval**
- [ ] Case detail carries an entry point into the workspace
- [ ] Case detail shows a package status card — profile, status, unresolved error count, approval state
- [ ] Deep-linking to a tab works (tab state in the route, not component-local only)
- [ ] The stale route comment is gone (`DR-15`)
- [ ] Frontend specs cover tab routing and the status card (`DR-14`)

## Current state

**The functionality is delivered and reachable.** This is a consolidation requirement, not a
capability gap — a distinction the register previously lost by recording it as `OPEN`.

`MappingReviewComponent` imports and embeds the two components that carry the rest of the lifecycle:

```
frontend/src/app/features/forms-package/
├── mapping-review/mapping-review.component.ts        ← routed; imports the two below
├── validation-readiness/validation-readiness.component.ts   ← embedded child
└── package-approval/package-approval.component.ts           ← embedded child
```

`mapping-review.component.ts` :25 —
`imports: [CommonModule, FormsModule, RouterLink, ValidationReadinessComponent, PackageApprovalComponent]`

So a consultant can already preview mappings, generate and download drafts (:123), review readiness
by severity, resolve non-error issues (`package-approval` :70), approve with acknowledgement (:78),
and download the package zip (:88).

**What is missing is the shell, not the substance.**

| Gap | Evidence |
| --- | --- |
| No `FormsPackageWorkspaceComponent` | No such file under `features/forms-package/` |
| No tabbed navigation — the three views stack in one scrolling page | `mapping-review.component.ts` composition |
| No case-detail entry point or status card | `case-detail.component.ts` |
| The route comment is false | `app.routes.ts` — *"Replaced by the full `FormsPackageWorkspaceComponent` in Milestone 5"*, next to a route loading `MappingReviewComponent`. This is `DR-15` |
| Two components are reachable only as embedded children | `validation-readiness` and `package-approval` have no route of their own |
| No specs | 0 frontend test files (`DR-14`) |

## Why it is `PARTIAL`, not `OPEN`

The 2026-08-21 pass recorded this `OPEN` because the named component does not exist. But the
acceptance question is whether a consultant can complete the package lifecycle in the UI — and they
can. Recording it as `OPEN` implied the M5 backend had no interface at all, which contributed to the
plan sizing Phase 1 at thirteen items rather than five.

**The remaining work is real but small:** a shell component, tab routing, and a case-detail card.

## Sequencing note

Best done **after** `F41-12` (admin editors), not before. Both are Angular work in the same feature
area, and the workspace shell is the natural place to surface catalogue state that `F41-12` makes
editable. Doing the shell first means touching it twice.
